# 教育決策系統（Educational Decision System, EDS）方法論 v1.0

> **前身為「國中會考命題決策矩陣（EDM）方法論」。** 更名原因：Exam 限定了這套方法只能用在單一考試，但核心設計（知識矩陣＋命題證據＋學習決策）可以套用到任何科目、任何考試，甚至任何學習情境，因此把名稱裡限制範圍的「Exam」拿掉，改用更準確的 **Educational Decision System（EDS）**。內部結構、模組內容完全不變，純粹是名稱與定位升級。

> **EDS 是一個以知識矩陣為基礎、以歷屆命題為證據、以學習決策為目的的教育決策系統。**
> 它不是用來分析會考，而是用來決定下一步該學什麼——分析（頻率、陷阱題、命題模板、ROI）只是手段，不是目的，它們都是中間結果，真正的目的是把有限的讀書時間分配到最有價值的地方。

> **第一志願 = 知識矩陣 × 命題決策 × 有效學習**
>
> - **知識矩陣**：知道「學什麼」（見獨立文件《自然科學領域_知識矩陣》，本文件不重複收錄代碼內容）
> - **命題決策**：知道「考什麼、怎麼考、哪些值得優先」（本文件第一～四章）
> - **有效學習**：把分析結果轉化為具體讀書策略與時間配置（本文件第五章）

## 三層架構（Three-Layer Architecture）

EDS 由三層構成，各自回答不同層次的問題：

| 層級 | 名稱 | 回答的問題 | 對應內容 | 變動頻率 |
|------|------|-----------|---------|---------|
| Layer 1 | Knowledge Layer（知識層） | 學什麼？ | 《自然科學領域_知識矩陣》：X 軸、Y 軸、代碼、關聯知識 | 幾乎不變（SSOT） |
| Layer 2 | Decision Layer（決策層） | 怎麼決定？ | 本文件 Module A-D：頻率、陷阱、Priority、ROI、Stability | 隨逐題標記資料更新而變動 |
| Layer 3 | Application Layer（應用層） | 今天做什麼？ | 本文件第五章：決勝圖譜、每日學習建議 | 隨學生剩餘時間/目標即時產生 |

### 四引擎對照表（概念透鏡，非重新命名）

以下是另一種理解四個模組的角度——把它們看成「四個回答不同決策問題的推理引擎」，而不只是「四種分析」。**這只是一個對照視角，Module A-D 的標題與內容維持不變**，避免每輪都重新命名造成版本混亂：

| 概念上的 Engine | 回答的問題 | 對應現有模組 |
|----------------|-----------|-------------|
| Knowledge Engine | 考什麼？ | Module A：命題分析（高頻／穩定度） |
| Assessment Engine | 怎麼考？ | Module C：命題模式（題型／命題模板／攻略） |
| Learning Engine | 哪裡該加強、怎麼學？ | Module B：失分分析（陷阱／失分原因／迷思） |
| Decision Engine | 今天先做什麼？ | Module D：Decision Engine（Priority／ROI／Recoverability） |
| Adaptive Engine（第五個，尚未實作） | 學生答錯了，下一步怎麼調整？ | 見文末「未來路線圖：Engine 5」 |

> 本文件是**方法論**，架構凍結為 v1.0；未來擴充（新科目、新指標）以「模組」形式加入 Module A-D 或新增章節，不回頭更動第一章核心原則與整體架構。知識矩陣本體與本文件分開維護，知識矩陣是 SSOT，不因應分析需要而改動。

### 「決勝圖譜」在這個系統裡的角色

「決勝圖譜」指的是 **Layer 3（Application Layer）最終交到學生手上的那個畫面**——不是分析過程本身，而是把 Layer 2 算出來的頻率、陷阱、Priority、ROI 這些數字，收斂成一張學生一眼就能看懂的圖／卡片（見第五章「學生輸出」）。它是整個系統的**出口**，不是中間站：Layer 1 告訴學生「有哪些東西」，Layer 2 告訴學生「哪些值得注意」，決勝圖譜則回答最後也是最關鍵的一句——「我現在要先讀哪個？」。日後若做成互動網頁（見第五章「Decision Graph」），也是在這個位置擴充，不會變成獨立的第四層。

## 第一章：核心原則（Principles）

### 原則一：Single Source of Truth（SSOT）
所有分析共用同一套知識矩陣代碼（見《自然科學領域_知識矩陣》）。禁止為了某項分析方便，另外建立第二套知識點分類。未來擴充到數學、社會等科目時，各科應各自維護一份對應的知識矩陣 SSOT，但方法論架構（本文件）共用。

### 原則二：Data-driven First（資料驅動優先）
所有排行榜、命題模板、題型對應、Priority Score，均須由逐題標記資料計算產生。若目前資料不足以支持某項結論，一律標示「⏳ 待驗證／待填」，不以經驗推測或通用建議替代實證結果。

### 原則三：Teaching Judgment（教學設計欄位獨立標示）
以下欄位**不是**由資料統計出來的，而是使用者的教學/學習經驗判斷：可救程度（Recoverability）、預估補強時間、題型攻略筆記、命題模板的最終確認。這類欄位在所有表格中一律用「🧑‍🏫 教學判斷」標示，與「📊 資料統計」欄位視覺上明確區分，不混為一談。

### 原則四：Iterative Update（逐年迭代更新）
不需要等 5 年資料全部標記完才開始分析。每完成一年的逐題標記，就重新跑一次 Module A-D 的計算，觀察排行榜與命題穩定度是否隨新資料變動。分析是持續滾動更新的，不是一次性產出。

### 原則五：Decision Relevance（決策相關性）
> **每一個分析模組，都必須回答一個學生真正需要做出的決策，否則不放入主系統。**

這條原則的優先度高於「這個分析方法看起來很嚴謹」——新增任何模組前，先問一句：**它能改變學生今天的決策嗎？** 如果答案是不能（例如單純算出更多描述性統計量，卻不對應任何一個「該不該投入時間」的判斷），就不放進 Module A-D，最多放進附錄當作進階/選用的驗證工具。

**現有模組驗證**（皆通過此原則）：

| 模組 | 對應的決策問題 |
|------|----------------|
| 高頻分析（A-1） | 這個範圍值得投入時間嗎？ |
| 命題穩定度（A-2） | 值得長期投資，還是只是曇花一現？ |
| 陷阱題分析（B-1） | 哪裡最容易丟分？ |
| 失分原因細分（B-2） | 該用什麼方式補救（讀書／練計算／練圖表／練推理／練審題）？ |
| 常見迷思排行榜（B-3） | 該優先矯正哪個錯誤想法？ |
| 題型對應／命題模板（C-1, C-2） | 該用什麼準備方式應對這個知識點？ |
| 題型攻略（C-3） | 哪個題型最需要優先刻意練習？ |
| Priority Score（D-1） | 眾多主題裡，哪個該先讀？ |
| Recoverability（D-2） | 現在值得花時間補嗎？ |
| Expected Score Gain（D-3） | 同樣的時間，投資在哪裡效益最高？ |

## 第三章：執行流程（Pipeline）

```text
STEP 1   建立知識矩陣（SSOT，已完成 — 見《自然科學領域_知識矩陣》）
   ↓
STEP 2   逐題標記（建立共用基礎資料表，見第四章共用基礎）
   ↓
STEP 3   高頻分析（Module A）
   ↓
STEP 4   陷阱分析 + 失分原因細分 + 常見迷思排行榜（Module B）
   ↓
STEP 5   Y×題型分析 + 命題模板 + 題型攻略（Module C）
   ↓
STEP 6   命題穩定度分析（Module A）
   ↓
STEP 7   Priority Score（三種模式：保A／A+／A++）（Module D）
   ↓
STEP 8   Recoverability 可救程度標註（Module D，教學判斷欄位）
   ↓
STEP 9   Expected Score Gain 分數效益分析（Module D）
   ↓
STEP 10  第一志願必會清單 Top 15 + 投資報酬率排行榜（Module D）
   ↓
STEP 11  學生輸出：決勝圖譜（第五章）
   ↓
STEP 12  更新 ARL 成熟度（第六章），回到 STEP 2 迭代下一年資料
```

> 每個 STEP 對應下方 Module A-D 或第五、六章的具體做法與公式，不需要照順序一次做完——但後面步驟通常依賴前面步驟的輸出（例如 STEP 9 效益分析需要 STEP 7 的 Priority Score 與 STEP 8 的可救程度都完成）。

## 第四章：分析模組（Modules）

### 共用基礎：逐題標記資料表

把每一屆、每一題標記成一列，至少包含以下欄位：

| 欄位 | 說明 | 欄位性質 |
|------|------|---------|
| 年份 / 題號 | 識別用 | 📊 |
| 科目 | 理化／生物／地科／跨科 | 📊 |
| X 軸主代碼 | 該題主要測驗的學習內容代碼（例：Bc-Ⅳ-3），對應知識矩陣 | 📊 |
| X 軸次代碼 | 該題連帶涉及的其他代碼，可留白，供命題模板分析使用 | 📊 |
| Y 軸代碼 | 該題主要測驗的學習表現代碼（例：pa-Ⅳ-2），對應知識矩陣 | 📊 |
| 題型 | 依下方「題型編碼手冊」分類 | 📊 |
| 通過率 | 官方或自行統計的逐題通過率 | 📊 |
| 失分原因 | 概念錯誤／計算錯誤／圖表判讀／推理不足／看錯題（見 Module B） | 📊（依陷阱題交叉分析研判）|
| 可救程度 | 高／中／低（見 Module D） | 🧑‍🏫 |
| 預估補強時間 | 小時數 | 🧑‍🏫 |

標記時建議**人工複核**而非純關鍵字比對——同一題常同時涉及 2-3 個 X 軸代碼，取「該題主要測驗的那一個」為主代碼，其餘列為次代碼。5 年 × 25 題 ≈ 125 題，分散在 226 個細代碼上會太稀疏，**統計時建議先做到「次主題」層級**（約 50 個），樣本數才有意義。

### 題型編碼手冊（決策優先順序）

同一題常常同時牽涉計算、圖表、閱讀，容易造成不同人標記結果不一致。建議依以下**優先順序**由上而下判斷，符合第一條就停止：

1. 若作答需要實際數學計算（含代入公式求數值）→ **計算題**
2. 否則，若主要資訊來源是圖形/表格，且解題核心是「讀出/判讀數據」→ **圖表判讀**
3. 否則，若題目描述一個實驗流程，核心是判斷變因/步驟/器材操作 → **實驗設計**
4. 否則，若核心在於理解一段較長的文字敘述或情境描述才能作答 → **閱讀理解**
5. 否則，若考的是科學史、科學家、科學與社會議題 → **科學史與社會**
6. 以上皆非，考的是單一概念是否正確 → **概念辨析**

### Module A：命題分析（考什麼、怎麼變化）

包含：高頻分析、命題穩定度分析。

#### A-1 高頻分析

**目的**：找出歷屆會考實際最常出現、且真正值得投入時間的學習內容範圍。

1. 以「X 軸次主題」為單位，統計每個次主題被標記為主代碼的次數，並計算平均通過率。
2. 依累積覆蓋率排序，不用硬切「前 20-30%」：往下累加題數，直到累積覆蓋約 70% 的題目為止列為「核心範圍」；累積到 90% 為止的列為「延伸範圍」；其餘列為「低頻範圍」。
3. 用「科目對應」表把次主題次數加總回科目層級，得到各科實際佔比。

```python
import pandas as pd
df = pd.DataFrame(records)  # records 為逐題標記資料
grouped = df.groupby('x軸次主題').agg(
    次數=('通過率', 'size'),
    平均通過率=('通過率', 'mean')
).reset_index().sort_values('次數', ascending=False)
grouped['累積題數'] = grouped['次數'].cumsum()
grouped['累積覆蓋率'] = grouped['累積題數'] / grouped['次數'].sum()
```

**完成後填入**：

| 次主題 | 出現次數 | 平均通過率 | 累積覆蓋率 | 分類 |
|--------|---------|-----------|-----------|------|
| ⏳ 待填 | ⏳ | ⏳ | ⏳ | 核心／延伸／低頻 |

#### A-2 命題穩定度分析（Stability Score）

**目的**：區分「每年幾乎都考」跟「最近才變熱門」這兩種完全不同的意義——前者代表核心地位穩固，可以放心投入；後者代表命題風向正在轉變，要多留意最近一兩年的實際出法。

**做法**：不是只看「五年總共出幾題」，而是逐年記錄「有沒有出現」，計算：
- **出現率**：5 年中出現的年數 ÷ 5
- **連續性**：是否連續出現（例如近 3 年連續出現，比中間斷過更穩定）
- **近期權重**：給最近 1-2 年較高的權重，反映命題風向的最新狀態

```python
stability = df.groupby(['x軸次主題', '年份']).size().unstack(fill_value=0)
stability_binary = (stability > 0).astype(int)
出現率 = stability_binary.mean(axis=1)
# 近期權重範例：越近期權重越高
weights = {111: 0.1, 112: 0.15, 113: 0.2, 114: 0.25, 115: 0.3}
穩定度分數 = sum(stability_binary[y] * w for y, w in weights.items() if y in stability_binary.columns)
```

**完成後填入**：

| 次主題 | 111 | 112 | 113 | 114 | 115 | 出現率 | 穩定度分數 | 判讀 |
|--------|-----|-----|-----|-----|-----|--------|-----------|------|
| ⏳ 待填 | ✓/✗ | ✓/✗ | ✓/✗ | ✓/✗ | ✓/✗ | ⏳ | ⏳ | 核心穩定／近期竄升／偶發 |

> 此分數會取代原本 Priority Score 公式中的「趨勢斜率」分量（見 Module D），更精確反映命題模式。

### Module B：失分分析（哪裡容易失分、為什麼）

包含：陷阱題分析、失分原因細分、常見迷思排行榜。

#### B-1 陷阱題分析

**目的**：找出「大家普遍答錯」的題目，這是拉開高分與中等分數差距的關鍵——第一志願不是靠 90% 的送分題贏的，是靠最後那 10-15% 的難題贏的。

**陷阱題門檻用統計方法，不用固定百分比**：改用該批資料自身的分布定義門檻，二選一：
- 方法一（絕對門檻）：通過率 < 40%
- 方法二（相對門檻，較嚴謹）：通過率 < 平均通過率 − 1 個標準差

```python
mean_p = df['通過率'].mean()
sd_p = df['通過率'].std()
threshold = min(40, mean_p - sd_p)
trap_questions = df[df['通過率'] < threshold]
```

#### B-2 失分原因細分

不要只停在「難」，把陷阱題進一步分類成五種失分原因，每種對應不同的具體對策：

| 失分原因類型 | 判斷依據 | 對策 |
|-------------|---------|------|
| 概念錯誤 | 學生對知識點本身理解有誤 | 重讀課本、釐清定義 |
| 計算錯誤 | 觀念正確但運算過程出錯 | 大量練計算，注意單位換算 |
| 圖表判讀 | 讀不懂圖表提供的資訊 | 練圖表判讀專項題 |
| 推理不足 | 知道個別知識點，但無法串連成推論 | 練跨章節整合題 |
| 看錯題 | 知道怎麼解，但誤讀題目條件/問法 | 練審題習慣，圈關鍵字 |

判斷方式：對照陷阱題的錯誤選項分布（如果拿得到選項作答分布），或依題目性質人工歸類到最符合的一類。

**完成後填入**：

| 陷阱題排名 | 年份/題號 | 通過率 | X 軸代碼 | Y 軸代碼 | 題型 | 失分原因 |
|-----------|----------|--------|---------|---------|------|---------|
| ⏳ 待填 | ⏳ | ⏳ | ⏳ | ⏳ | ⏳ | 概念錯誤／計算錯誤／圖表判讀／推理不足／看錯題 |

#### B-3 常見迷思排行榜

|------|---------------------|-------------|---------|---------|
| ⏳ 待填 | ⏳ | ⏳ | ⏳ | ⏳ |

### Module D：Decision Engine（決策引擎）

包含：Priority Score（三模式）、Recoverability、Expected Score Gain、Top15、投資報酬率排行榜。

> **概念定位**：Decision Engine 不是單一分數，而是一個可以帶入不同參數、動態運算的函式，內部組合了 Priority Score、ROI、Recoverability、Stability（來自 Module A-2）等子演算法，最終輸出排序後的 Top N 建議：
>
> ```text
> DecisionEngine(
>     目標 = 'A++',              # 保A / A+ / A++，對應 D-1 三種權重模式
>     剩餘天數 = 30,
>     目前能力 = ⏳,              # 需個人化評測資料，v1.0 暫無來源，可先用「科目平均通過率」代替
>     Recoverability = 個人標註表  # 來自 D-2
> )
> → 輸出：依效益排序的 Top N 主題清單
> ```
>
> ⚠️ **v1.0 誠實聲明**：「目前能力」這個輸入需要學生個人的模考/自評資料，目前 EDS 沒有蒐集這類資料的機制，因此 v1.0 的 Decision Engine 實際上是**手動重跑的計算腳本**（依 D-1~D-5 的公式，換參數重新算一次），而不是即時互動的個人化引擎。若要做到真正的個人化動態運算，需要先建立「個人能力檔案」資料來源，見文末「未來路線圖：Engine 5」。

#### D-1 Priority Score（三種模式）

不同目標的學生，最佳權重不同——保 A 的人最怕丟送分題，第一志願的人最怕最後幾題拿不到，因此提供三種預設模式，也可自訂權重：

| 模式 | 頻率 | 難度 | 趨勢/穩定度 | 整合複雜度 | 適用對象 |
|------|-----:|-----:|-----:|-----:|---------|
| 保 A | 60% | 20% | 10% | 10% | 目標求穩，優先不丟核心分數 |
| A+ | 45% | 30% | 15% | 10% | 已掌握核心，開始拉高分數 |
| A++／第一志願 | 35% | 35% | 20% | 10% | 目標拉開差距，難題也要拿下 |

```python
def normalize(s):
    return (s - s.min()) / (s.max() - s.min())

def priority_score(grouped, mode='A++'):
    weights = {
        '保A': (0.60, 0.20, 0.10, 0.10),
        'A+': (0.45, 0.30, 0.15, 0.10),
        'A++': (0.35, 0.35, 0.20, 0.10),
    }
    w1, w2, w3, w4 = weights[mode]
    return (
        w1 * normalize(grouped['次數']) +
        w2 * normalize(100 - grouped['平均通過率']) +
        w3 * normalize(grouped['穩定度分數']) +   # 來自 Module A-2
        w4 * normalize(grouped['次代碼平均數'])
    )
```

> 權重可依個人考試策略自訂，但務必**公開透明並附理由**，避免變成主觀黑盒子。

#### D-2 Recoverability（可救程度）🧑‍🏫

同樣的難度，補救成本可能天差地遠——通過率 25% 但兩小時就能補起來，比通過率 25% 但需要半年才能補起來更值得優先。這一欄**不是統計值**，是使用者對「這個知識點好不好補救」的教學判斷（例如：只是記憶點 vs. 需要整套先備推理鏈）。

| 可救程度 | 說明 | 預設補強時間區間（可自行覆寫） |
|---------|------|------------------------------|
| 高 | 記憶點、單一概念，讀懂即可 | 1-2 小時 |
| 中 | 需要理解＋練習才能內化 | 3-5 小時 |
| 低 | 需要先備知識鏈完整、涉及多章節整合 | 6 小時以上 |

#### D-3 Expected Score Gain（分數效益分析）

**目的**：把「重要」和「划算」分開看——一個主題再重要，如果補強成本很高，在時間有限的前提下未必是最優解。

```
效益 = Priority Score ÷ 預估補強時間
```

```python
grouped['效益'] = grouped['Priority Score'] / grouped['預估補強時間_小時']
grouped_sorted = grouped.sort_values('效益', ascending=False)
```

**完成後填入**：

| 主題 | Priority Score | 可救程度 | 預估補強時間 | 效益 |
|------|----------------|---------|-------------|------|
| ⏳ 待填 | ⏳ | ⏳ | ⏳ | ⏳ |

#### D-4 投資報酬率排行榜（星等視覺化）

| 主題 | 出題頻率 | 平均通過率 | Priority Score | 評等 |
|------|---------|-----------|----------------|------|
| ⏳ 待填 | ⏳ | ⏳ | ⏳ | ★☆☆☆☆ ~ ★★★★★ |

> 評等建議：Priority Score 落在前 20% → ★★★★★；20-40% → ★★★★☆；40-60% → ★★★☆☆；60-80% → ★★☆☆☆；其餘 → ★☆☆☆☆

把 Priority Score（或效益）排名前 15 的次主題獨立列出，這是有限時間內**最優先讀熟**的範圍：

## 未來路線圖（v1.1+，尚未實作）：Engine 5 — Adaptive Engine

以下是 EDS 的長期願景——一個可持續運作的**閉環系統（Closed Loop）**，也就是四引擎對照表中提到的第五個引擎「Adaptive Engine」，回答的問題是「學生答錯了，下一步怎麼調整？」。目前坊間多數會考整理只是「試題→整理重點→學生讀」的單向流程，EDS 未來希望做到：

```text
Knowledge Layer（知識矩陣，SSOT，不變動）
        │
        ▼
Decision Layer：逐題標記 → 命題分析 → Decision Engine
        │
        ▼
Application Layer：決勝圖譜 → 學生依建議讀書
        │
        ▼
Exam Mock（學生模擬考，⏳ 需新建資料蒐集機制）
        │
        ▼
作答結果 → 更新「個人能力檔案」（⏳ 新增資料表，屬 Decision Layer）
        │
        └──────────────┐
                        ▼
              回饋 Decision Engine 的「目前能力」參數
              （不回饋 Knowledge Layer／知識矩陣本體）
```

> **與原始建議的差異說明**：原建議的閉環是「回饋知識矩陣」，這裡修正為「回饋個人能力檔案（Decision Layer）」——知識矩陣是 108 課綱代碼與內容的 SSOT，不應該因為某個學生模考表現而被改動；真正該被學生資料更新的，是「這個學生對某個代碼的掌握程度」這個決策層級的動態變數。

**要落地這個閉環，尚缺的基礎建設**：
1. 個人能力檔案資料表（記錄每個學生對每個 X 軸代碼的掌握度估計，初始值可用「班級/全國平均通過率」代替）
2. Exam Mock 機制（讓學生的模考作答結果可以逐題對應回知識矩陣代碼，才能更新上述能力檔案）
3. Decision Engine 從「手動重跑腳本」升級為可即時查詢「目前能力」參數的互動工具

這三項目前都不存在，v1.0 暫不實作，僅作為文件化的方向紀錄，避免日後忘記這個設計曾經被考慮過。



以下工具不會直接幫學生多拿分，只在您想確認「這個分析結論夠不夠可靠」、或要把矩陣分享給其他老師/同學共用時才需要。

### 交叉分析總覽

| 交叉組合 | 回答的問題 |
|---------|-----------|
| X 軸代碼 × 通過率 | 哪些知識點最難？（難度地圖） |

### 統計顯著性驗證（卡方檢定 + Cramér's V）

用來確認 Module C「題型對應分析」「命題模板」看到的集中趨勢是真規律還是巧合：

```python
from scipy.stats import chi2_contingency
crosstab = pd.crosstab(df['y軸代碼'], df['題型'])
chi2, p, dof, expected = chi2_contingency(crosstab)
low_expected_cells = (expected < 5).sum()
print(f'期望次數<5的格子數：{low_expected_cells} / {expected.size}（若偏多，改用 Fisher exact test）')
print(f'卡方值={chi2:.2f}, p值={p:.4f}')

n = crosstab.sum().sum()
cramers_v = (chi2 / (n * (min(crosstab.shape) - 1))) ** 0.5
print(f"Cramér's V = {cramers_v:.3f}")
```

### 分類信度驗證（Cohen's Kappa）

適用於這份分析要發表、給其他老師/同學共用，或作為公開題庫依據時。找一位協同標記者獨立標記同一批題目（至少抽樣 30-50 題）：

```python
from sklearn.metrics import cohen_kappa_score
kappa = cohen_kappa_score(標記者A的題型列表, 標記者B的題型列表)
```
κ ≥ 0.81 幾乎完全一致；0.61-0.80 高度一致；0.41-0.60 中度一致，建議討論分歧題目後重新標記。

### 鑑別度分析（需要逐生成績資料）

若能取得逐生作答資料（不只是整體通過率），把學生依總分排序，取前 27% 為高分組、後 27% 為低分組：

```
鑑別度 D = 高分組該題通過率 − 低分組該題通過率
```
D ≥ 0.4 優良、0.2-0.39 可接受、< 0.2 建議檢視題目品質。**注意**：單純的整體通過率無法回推這個指標，若手上只有彙總通過率則此節略過。
